# Занятость шкафчиков — СПОРТ МЕДИА

Внутренний продукт для публичного просмотра и управления занятостью шкафчиков
и раздевалок в фитнес-клубах.

- **Публичная часть** (`/`) — без авторизации: занятость по месяцам, слотам
  и раздевалкам, поиск, фильтры по сети/городу/статусу, цветовая индикация,
  карточка клуба с таймлайном на год.
- **Админ-панель** (`/admin`) — вход через Supabase Auth: правки занятости,
  закрытие раздевалок и слотов, брони, справочник клубов и вместимости,
  импорт адресной программы, журнал изменений.

## Модель данных

```
lockers_clubs        каталог клубов из АП (независим от public.clubs дашборда)
  └ dashboard_club_id → public.clubs.id   опциональная ссылка, nullable

lockers_capacity     вместимость раздевалки: клуб × раздевалка × поверхность
lockers_occupancy    занятость из АП:  клуб × месяц × слот × раздевалка
lockers_overrides    ручные правки админа — ПРИОРИТЕТ над импортом
lockers_imports      история загрузок АП
lockers_import_rows  сырые строки импорта для дифф-предпросмотра
lockers_admin_log    журнал всех действий
lockers_admins       кто имеет доступ к панели
```

Итоговые цифры интерфейс получает не из таблиц напрямую, а из SQL-функции
`lockers_availability(month, surface)`, которая накладывает ручные правки
поверх импорта:

```
всего     = override.total_override    ?? capacity.total_lockers ?? 0
занято    = override.occupied_override ?? occupancy.occupied     ?? 0
свободно  = всего − занято − бронь
статус    = override.status ?? (всего = 0 → closed | бронь > 0 → reserved | available)
```

### Смысл полей АП

| Колонка в АП | Куда идёт |
| --- | --- |
| `Фитнес-клуб` | `lockers_clubs.name` |
| `Адрес клуба`, `Город` | `lockers_clubs.address`, `.city` |
| `Количество` | вместимость раздевалки (`lockers_capacity.total_lockers`) |
| `Статус конструкций` | занятость: `Готовы к размещению` / `Занято с … по …` / `Занято до …` |
| `Слот` | `1` или `2` — два рекламных места на дверце шкафчика |
| `Зона расположения (список)` | `male` / `female` |
| `Тип конструкции` | `lockers` (шкафчики) / `mirrors` (зеркала в раздевалке) |
| `Дата старта РК` | период РК; может содержать список свободных окон `01.09-30.09, 01.11-31.12` |

Парсер ищет колонки **по названиям заголовков, а не по буквам** — в разных
листах одной и той же АП колонки съезжают на одну-две позиции. У каждого поля
список синонимов и запасной поиск по подстроке; строка, которую не удалось
разобрать, не роняет импорт, а попадает в предпросмотр с пометкой проблемы.

NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co

## Установка схемы БД

Если разворачиваете на новом проекте Supabase — выполните `supabase/schema.sql`
в SQL Editor. На текущем проекте схема уже применена.

> `schema.sql` ссылается на `public.clubs` (таблица дашборда кампаний) в поле
> `dashboard_club_id`. На проекте без этой таблицы удалите строку
> `dashboard_club_id uuid references public.clubs(id) …` перед выполнением.

## Выдать доступ администратору

1. Supabase → **Authentication → Users → Add user**, создать пользователя
   с почтой и паролем (галочка «Auto Confirm User»).
2. Добавить его в администраторы:

```sql
insert into lockers_admins (user_id, email)
select id, email from auth.users where email = 'name@company.ru';
```

Пользователь, вошедший без записи в `lockers_admins`, увидит экран «Доступ не
выдан» с готовым SQL-запросом и своим `user_id`.

## Деплой на Vercel

1. Залить репозиторий на GitHub.
2. Vercel → **Add New → Project** → выбрать репозиторий (фреймворк определится
   как Next.js автоматически).
3. **Environment Variables** — добавить `NEXT_PUBLIC_SUPABASE_URL`
   и `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. Deploy.

Supabase → **Authentication → URL Configuration**: добавить домен Vercel
в `Site URL` и `Redirect URLs`.

## Импорт адресной программы

`/admin/import` → выбрать `.xlsx` → предпросмотр → «Применить к базе».

Что происходит при применении:

1. Клубы, которых нет в каталоге, создаются (сеть определяется по названию).
   У существующих дозаполняются пустые город и адрес — заполненные не
   перетираются.
2. Вместимость раздевалок обновляется из колонки «Количество».
3. Занятость проставляется по месяцам, которые АП помечает занятыми;
   в остальных месяцах файла занятость снимается.
4. **Ручные правки администратора не трогаются никогда.** В предпросмотре
   видно, сколько правок защищено.

Оба шага можно отключить галочками, если конкретная АП неполная.

## Цветовая индикация

| Цвет | Условие |
| --- | --- |
| Зелёный | свободно больше 60% |
| Жёлтый | свободно 25–60% |
| Красный | свободно меньше 25% |
| Фиолетовый | стоит бронь |
| Серый | закрыто или вместимость не заведена |
